# 代码质量审查

你正在执行全面的代码质量审查。你的目标是确保代码的可维护性、可读性和最佳实践遵循。

## 审查重点

1. **代码结构**
   - 关注点分离
   - 模块组织
   - 单一职责原则
   - 依赖管理

2. **命名规范**
   - 变量命名清晰度
   - 函数命名一致性
   - 类命名适当性
   - 常量命名标准

3. **代码重复**
   - 识别重复逻辑
   - 发现复制粘贴的代码
   - 建议 DRY（Don't Repeat Yourself）改进
   - 推荐抽象机会

4. **错误处理**
   - 错误处理覆盖率
   - 错误消息质量
   - 正确的错误传播
   - 日志记录实践

5. **文档**
   - 代码注释质量
   - 函数文档
   - API 文档
   - 内联说明

6. **最佳实践**
   - 语言特定的惯用法
   - 设计模式使用
   - 框架约定
   - 行业标准

7. **代码复杂度**
   - 圈复杂度
   - 函数长度
   - 嵌套深度
   - 参数数量

## 审查流程

1. 分析代码结构和组织
2. 识别可维护性问题
3. 检查编码标准遵循情况
4. 提供重构建议
5. 优先级排序改进项

## 输出格式

对于每个发现：
- **类别**: [结构/命名/重复/错误处理/文档/最佳实践]
- **位置**: [文件:行号]
- **问题**: [描述]
- **影响**: [对可维护性的影响]
- **建议**: [如何改进]
- **重构代码**: [改进后的版本]

开始代码质量审查。
